# Forktown — Design Context

## Target audience
Platform/engineering leads, staff engineers, and AI-agent platform teams at companies that ship dangerous migrations (billing, auth, DB, API versions). They need confidence an agent’s PR survives the real world—not just CI.

## Use cases
1. Spin up a “town” (living sim) around a codebase
2. Rehearse an agent-safe migration before touching prod
3. Watch the world attack the change (users, tickets, outages, legacy data)
4. Read a survival report and decide whether to ship

## Brand personality
Municipal modernist · cartographic · serious play. Feels like a city planner’s control tablet for software—not another neon AI dashboard. Warm sodium streetlight amber + cool infrastructure slate. Confident, slightly wry, never cute-emoji.

## Aesthetic direction
**Living cartography** — aerial town map as the product’s soul. Blocks = services, streets = APIs, neighborhoods = customer cohorts. Soft blue-gray fog fields, topographic grain, amber alert beacons, forest-green healthy districts. Display: Bricolage Grotesque. Body: Source Serif 4 for editorial weight. Mono only for sim telemetry, never as the brand voice.

## Differentiation
The interactive town map that *lives* while agents rehearse—not a chat UI, not an eval leaderboard.
